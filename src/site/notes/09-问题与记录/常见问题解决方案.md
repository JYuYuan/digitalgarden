## React 相关

### 问题 1：React 16 升级到 React 18

**适用项目**：[[02-Web端项目/tpm-pc-manager\|tpm-pc-manager]]

**问题描述**：

- 需要升级 React 16.13.1 到 React 18
- Ant Design 4 到 5 的兼容性

**解决方案**：先明确迁移范围，再分步调整依赖与入口。以下为迁移参考，项目当前状态以 [[02-Web端项目/tpm-pc-manager\|tpm-pc-manager]] 和源码为准。

**1. 升级 React 依赖**

```bash
npm install react@18 react-dom@18
```

**2. 修改 React 入口文件**

```jsx
// 旧写法
ReactDOM.render(<App />, document.getElementById('root'));

// 新写法
import { createRoot } from 'react-dom/client';
const root = createRoot(document.getElementById('root'));
root.render(<App />);
```

入口代码中的 `App` 沿用现有导入，并确认 `root` 容器存在；使用 TypeScript 严格检查时还需处理 `getElementById` 可能返回 `null` 的情况。

**3. 需要迁移 Ant Design 时再调整依赖**

```bash
npm install antd@5
```

**注意事项**：

- React 18 的 Automatic Batching 可能影响现有代码
- Ant Design 5 有破坏性更新，需要查看迁移指南
- 第三方组件库可能需要同步升级

### 问题 2：Redux Toolkit 最佳实践

**适用项目**：[[02-Web端项目/tpm-pc-manager\|tpm-pc-manager]]

**使用条件**：项目已采用 Redux Toolkit 时，用 `createSlice` 组织状态与 action；此例只包含 slice，store 注册和页面连接沿用项目现有方式。

**推荐写法**：

> [!example]- 展开代码示例 · typescript
> ```typescript
> // 使用 createSlice
> import { createSlice, PayloadAction } from '@reduxjs/toolkit';
>
> interface UserState {
>   name: string;
>   age: number;
> }
>
> const userSlice = createSlice({
>   name: 'user',
>   initialState: { name: '', age: 0 } as UserState,
>   reducers: {
>     setUser: (state, action: PayloadAction<UserState>) => {
>       state.name = action.payload.name;
>       state.age = action.payload.age;
>     }
>   }
> });
>
> export const { setUser } = userSlice.actions;
> export default userSlice.reducer;
> ```

## UmiJS 相关

### 问题 3：UmiJS 4 环境变量配置

**适用项目**：[[02-Web端项目/bss-frontend\|bss-frontend]]

**配置方法**：`define` 在构建时注入常量，配置文件读取环境变量后提供给前端代码。`API_BASE_URL` 为示例字段，需与实际启动环境保持一致。

```typescript
// config/config.ts
export default {
  define: {
    API_BASE_URL: process.env.API_BASE_URL || 'http://localhost:3000'
  }
};

// 使用
console.log(API_BASE_URL); // 直接使用
```

## 小程序相关

### 问题 4：微信小程序 npm 包使用

**适用项目**：[[03-小程序项目/andromeda-wx\|andromeda-wx]]

**使用条件**：原生微信小程序通过开发者工具构建 npm；Taro 等框架项目先按项目页的编译流程处理。

**步骤**：

1. 在项目根目录执行 `npm install`
2. 在微信开发者工具中：工具 → 构建 npm
3. 在代码中引入：`import lib from 'package-name'`

**常见问题**：

- 构建后找不到包 → 检查 `package.json` 中的包是否在 `dependencies`
- 报错 `module not found` → 删除 `miniprogram_npm` 重新构建

## 性能优化

### 问题 5：大列表渲染优化

**适用场景**：渲染项很多、可只渲染可视区域的列表。示例依赖提供 `FixedSizeList` API 的 `react-window` 版本，按固定 50px 行高渲染；先核对已安装依赖和内容高度，再接入实际数据。

**解决方案**：

```jsx
// 使用虚拟滚动
import { FixedSizeList } from 'react-window';

const VirtualList = ({ items }) => (
  <FixedSizeList
    height={600}
    itemCount={items.length}
    itemSize={50}
    width="100%"
  >
    {({ index, style }) => (
      <div style={style}>{items[index]}</div>
    )}
  </FixedSizeList>
);
```

## 构建部署

### 问题 6：Webpack 构建速度优化

**适用项目**：[[02-Web端项目/tpm-pc-manager\|tpm-pc-manager]]

**优化方案**：下面的 `filesystem` 持久化缓存适用于 Webpack 5，Webpack 4 项目不能直接套用整段配置。`thread-loader`、`ts-loader` 也依赖项目已有安装与 loader 兼容性；先定位构建耗时，再选用对应部分并比较前后结果。

> [!example]- 展开代码示例 · javascript
> ```javascript
> // webpack.config.js
> module.exports = {
>   // 使用 cache
>   cache: {
>     type: 'filesystem'
>   },
>
>   // 优化 resolve
>   resolve: {
>     extensions: ['.js', '.jsx', '.ts', '.tsx'],
>     modules: ['node_modules']
>   },
>
>   // 使用 thread-loader
>   module: {
>     rules: [{
>       test: /\.tsx?$/,
>       use: ['thread-loader', 'ts-loader']
>     }]
>   }
> };
> ```
